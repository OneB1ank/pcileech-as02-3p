## System roles

The design connects two independent physical planes:

```text
controller host
  <-> controller 25G NIC
  <-> LC-LC optics
  <-> FPGA physical SFP1
  <-> RawUDP command/response transport

FPGA PCIe edge connector
  <-> target PCIe Root Complex
  <-> PF0 configuration, BAR0, CQ/CC and RQ/RC transactions
```

The controller NIC address exists only so Ethernet, ARP, IPv4, and UDP frames
can reach SFP1. The PCIe PF0 identity is generated by the PCIe4 IP/profile and
does not become a network-controller identity because a 25G cable is present.

The combined internal path is:

```text
controller 25G NIC
  <-> SFP1 / Taxi GTY + 25G MAC
  <-> Corundum Ethernet + ARP + IPv4 + UDP (64-bit AXIS)
  <-> AS02 RawUDP filter, peer state, CDC and word packing
  <-> IfComToFifo (64-bit RX / 256-bit TX)
  <-> reused asmcehnk FIFO and mux
  <-> reused BAR, config-shadow and raw-128 TLP framework
  <-> AS02 UltraScale+ adapters
  <-> PCIe4 CQ/CC/RQ/RC (256-bit at the hard-IP boundary)
```

## Transport receive path

1. Taxi terminates the SFP1 25GBASE-R link and emits complete Ethernet frames on
   a 64-bit AXIS interface.
2. A Taxi asynchronous frame FIFO crosses the complete frame into the network
   processing domain. Crossing frame boundaries instead of isolated bytes
   preserves `tkeep`, `tlast`, and drop behavior under backpressure.
3. Corundum Ethernet, ARP, IPv4, and UDP blocks perform the standard protocol
   parsing. The AS02 wrapper answers ARP for `02:00:00:00:00:de`, accepts the
   configured local IPv4 address, checks the UDP destination port, and rejects
   unsupported traffic.
4. The UDP payload is converted into 64-bit asmcehnk protocol words with the
   byte/DWORD order expected by the original command FIFO.
5. `asmcehnk_fifo` classifies command, config, and TLP traffic. Existing
   command, loopback, BAR/config and raw-TLP semantics are retained.

The receiver is deliberately static: no DHCP, TCP, IPv4 fragmentation, jumbo
frame reassembly, or multi-session state is required for the compatibility
transport.

## Transport transmit path

1. The reused asmcehnk mux selects the next 256-bit response word according to
   the original response priority.
2. The AS02 packetizer applies the byte ordering formerly produced by the
   AMDUSB4 width-conversion path and divides responses into legal UDP payloads.
3. Corundum UDP/IPv4/Ethernet transmit logic generates checksums and headers.
4. The response is addressed to the most recent peer whose receive header
   passed the destination IPv4, UDP-port, UDP-length/eight-byte-alignment, and
   non-fragment policy. The current peer update does not include a destination
   MAC comparison or wait for later payload-integrity checks.
5. Taxi's MAC/GTY path transmits the response through physical SFP1.

The 64-bit MAC datapath can accept one eight-byte beat per network clock. The
selected low-latency Taxi clock is approximately 402.8 MHz, giving a raw AXIS
capacity of about 25.78 Gbit/s before protocol overhead. Sustained application
throughput still depends on frame size, inter-packet gaps, host processing,
backpressure, and PCIe transaction latency, so line-rate operation remains a
hardware measurement rather than a simulation-only claim.

## PCIe transaction paths

UltraScale+ PCIe separates traffic into four AXI-Stream interfaces:

| Interface | Direction relative to FPGA logic | AS02 role |
| --- | --- | --- |
| CQ | PCIe hard IP to user logic | Host requests targeting FPGA BAR/config handling |
| CC | User logic to PCIe hard IP | Completions returned for CQ requests |
| RQ | User logic to PCIe hard IP | FPGA-originated memory reads and writes |
| RC | PCIe hard IP to user logic | Host completions for FPGA memory reads |

The older 7-series design mixed request and completion packet types on one RX
and one TX stream. The AS02 adapters decode or construct the UltraScale+
descriptors while presenting the existing raw-TLP representation to the
framework:

```text
CQ descriptor + payload -> raw 128-bit request -> BAR/shadow logic
BAR raw completion      -> CC completion descriptor + payload
raw MRd/MWr             -> RQ request descriptor + payload
RC completion           -> raw 128-bit Cpl/CplD
```

Tag allocation, sequence tracking, `tkeep`, `tlast`, `tuser`, multi-beat
packetization, and backpressure are handled at this adapter boundary. The four
interfaces are connected; they are not tied off.

## Why raw TLP remains 128-bit

The reusable BAR, shadow, FIFO, mux, and host protocol were designed around
`IfAXIS128`. Changing that representation would affect command framing, BAR-hit
metadata, packet boundaries, golden vectors, and LeechCore compatibility.

The PCIe4 hard IP uses a 256-bit AXIS interface because that is the native
UltraScale+ endpoint boundary. Width conversion therefore belongs only in
`asmcehnk_pcie_tlp_us.sv` and related staging. Keeping 128-bit raw TLPs inside
the framework provides three invariants:

- the same DWORD order reaches the reused BAR/config/TLP logic;
- host-side RawUDP payloads do not gain an AS02-specific endian format;
- PCIe IP generation details remain isolated from the protocol core.

The network transmit side also consumes a 256-bit mux word, but that is a
transport packetization boundary, not a change to the raw-TLP contract.

## Configuration and BAR state

Several configuration views exist for different purposes and must not be
collapsed into one register file:

- PCIe4 hard-IP/config-management state controls what the Root Complex actually
  enumerates.
- `asmcehnk_tlps128_cfgspace_shadow` is the active framework shadow for raw
  configuration-TLP semantics.
- the local DRP/config mirror supplies the bounded register image expected by
  LeechCore commands.

`asmcehnk_pcie_cfgspace_shadow.sv` is retained as a content-locked legacy
reference but is not included in the AS02 active Vivado source roots and does
not decide the enumerated PF0 state.

BAR0 requests arrive on CQ, are translated into the original one-hot BAR-hit
and raw-TLP format, and are processed by the reused BAR controller. The reply
is converted to CC format. FPGA-originated host-memory access uses RQ/RC and is
separate from BAR0 servicing.

## Clock, reset, and backpressure

The principal domains are:

- PCIe user clock: 250 MHz;
- SFP1 MAC/network clock: derived from the 25G GTY path;
- board/system control clocks inherited from the Taxi shell.

Payloads cross domains through asynchronous frame or word FIFOs. Reset signals
are synchronized into their destination domains, and both sides of a soft-path
FIFO are flushed when the owning PCIe or network path resets. AXIS valid/data
must remain stable while ready is low; focused tests exercise this condition on
UDP, CQ/CC, and RQ/RC paths.

Generated PCIe reset structures and inherited Taxi GT reset crossings remain
visible in Vivado CDC reports. The project records them instead of hiding them
with broad waivers or rewriting third-party/generated logic solely to obtain an
empty report.

## Port and reuse policy

- Physical **SFP1** maps to `sfp_rx/tx[0]` and is the sole RawUDP transport.
- Physical **SFP2** maps to `sfp_rx/tx[1]`; TX valid remains low and RX is
  drained so it cannot carry transport frames.
- Chip-independent framework code is preserved where possible. Content-locked
  files are listed in `as02_asmcehnk_25g/reuse_manifest.json`.
- Migration-specific RTL is concentrated in the AS02 top, network boundary,
  CDC staging, configuration adapter, and CQ/CC/RQ/RC conversion.
- Taxi and Corundum are consumed only for their stated board/network roles;
  complete CNDM and mqnic applications are not part of the design.
